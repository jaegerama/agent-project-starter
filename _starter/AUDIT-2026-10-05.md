# Audit: the starter before its first public release (2026-10-05)

Scope: every tracked file of the private repository at its last commit (37
files, 19 commits), against the five dimensions of the audit brief, plus the
question the brief ends on: can this folder be made public and stay
maintainable by its own rules?

Method, so each claim can be checked:

- Every file read in full.
- Each suspected defect reproduced by a script in a throwaway copy of the
  starter: 19 hypotheses, 19 confirmed (three of them confirm that something
  works). One more, that a nested `.env` escaped the deny, was refuted live.
  Nothing below is reported from reading alone.
- Live tests in a Claude Code session on Windows 11 (Git Bash, Node 24.13.1),
  for what only a session can show: the hook after a `cd`, the shell and
  environment a hook runs with, the deny rules in `bypassPermissions` mode,
  nested `.env` files, `~/` patterns, and whether settings reload mid-session.
  Dummy files only, deleted afterwards.
- Platform facts from the Claude Code and Gemini CLI documentation. The
  documentation answer was wrong twice (deny rules in `bypassPermissions`
  mode, and `cat .env` in Bash) and right once (nested `.env`); the live
  result is what this report uses.
- Every fix was mutation-checked: broken again in a copy, the self-test red on
  the cases written for it and on nothing else. 27 mutations, 27 caught.

Severity follows `.claude/rules/review-severity.md`.

Before any change: `node _starter/selftest.mjs` 77 passed, 0 failed;
`node .claude/tools/agent-check.mjs` red on 64 template slots, which is by
design; `node tools/docs-drift.mjs` 0 passed, 2 skipped.

After: the self-test 120 passed, 0 failed, 0 skipped; agent-check red on 67
template slots, by design (the three found below are counted now);
docs-drift 1 passed, 2 skipped.

---

## 1. Executive verdict

**Defective as committed.** The design holds up: one rules file, pointers that
carry no rules, a slot gate that goes red on day one, and a self-test that pins
its own past defects. Most of the tooling does what it says. It was defective
because:

1. pushing its history would have published details of other private
   repositories;
2. it told autonomous agents to install third-party skills from the network;
3. its headline mechanism, the docs-first hook, failed open after one `cd`;
4. several checks had false greens of exactly the kind the starter exists to
   prevent, and one had a false red for three package managers.

**After the fixes in this release: ready with reservations.** The reservations
are structural, and `AGENTS.md` §11 states them instead of hiding them:

- In Claude Code the hook guards the file tools only. A file written through
  Bash is not seen; the gate stays red for it.
- The secret denies stop the Read tool and the common shell readers, not an
  interpreter one-liner. The sandbox that would stop it does not run on
  native Windows.
- In Codex, Cursor, Gemini CLI and Antigravity every process rule is still an
  intention. The gate, run by hand or by CI, is the only enforcement there.

### What held up

- No import loop: the only import in the repository is `CLAUDE.md:3`, and
  now `GEMINI.md:3`; neither target imports anything.
- No secret, token or AI trailer in any of the 19 private commits, and one
  author identity throughout.
- The slot pattern's exclusions (generic types, tags, emails, autolinks)
  behave as documented.
- adopt's private-mode preflight refuses before it writes anything.
- The hook blocked absolute paths with `..`, lowercase drive letters and
  forward slashes before this release too.
- `Read(./.env)` covers a `.env` in any subdirectory, and the denies hold in
  `bypassPermissions` mode.

## 4. The five dimensions, answered

**1. Token and context efficiency.** The architecture is right and was being
eroded: one rules file, pointers of 47 and 15 lines, no import loop. The
same-day additions put the severity ladder, the UI baseline and the process
rules in two places each, and two of the three copies had already drifted.
The 7-rung ladder is sound advice that constrains nothing by itself: no check
can tell a premature abstraction from a needed one. A reviewer can, using the
severity ladder.

**2. Security and guardrails.** Secrets: the Read tool and common shell
readers are denied, even in `bypassPermissions` mode; an interpreter one-liner
is not, and only the sandbox (macOS, Linux, WSL2) closes that. The hook was
bypassable five ways before this release (a `cd`, `..`, NotebookEdit,
`tools/`, its own allowlist) and one way after (Bash). Supply chain: nothing
prevents `npm install`, `pip install` or `go get` except Claude Code's default
prompt for commands that are not allowlisted, and the starter now says so. The
severity ladder is unambiguous; it is enforced by a reviewer, in every tool.

**3. Portability.** Codex, Cursor and Copilot read `AGENTS.md` natively;
Gemini CLI now imports it, documented but not yet observed; Antigravity is
unverified. Everything Claude Code enforces with a hook is an intention
elsewhere, and §11 has the table. Node is needed in every stack, for the
harness only, and a missing Node makes the hook fail open. No absolute
personal path remains. CI runs the harness on Ubuntu, macOS and Windows.

**4. PRD to Done.** Epic 0 first and one story in WIP were intentions; a
docs-drift check makes both mechanical wherever the gate runs. Nothing in a
repository can stop an agent writing a convincing terminal log into
`HANDOFF.md`. A gate re-run by someone other than that agent can: CI.

**5. SemVer and anti-slop.** The mapping was not clean (M3). The UI baseline
was explicit and wrong: it prescribed a pattern antislop lists as slop.
Explicit rules cannot prevent generic UI; antislop's answer is direction from
`DESIGN.md`, which only the owner can write.

## 6. Not done, and why

- A hook that refuses dependency installs. Possible, as a PreToolUse hook on
  Bash, but it would also block an install the owner approved, and a direct
  edit of the manifest bypasses it. The review is the real check.
- A check that every commit has a changelog entry. Entries are not keyed to
  commits, so a mechanical version would be noise.
- Bringing existing projects up to date. adopt does it, dry run first, and
  that is the owner's call per project.

## 7. Accepted limits (2026-10-07)

The owner accepted the two findings this audit left partly fixed as limits,
so none in it is open; every other finding is fixed, verified or documented.

- **B5.** The deny rules keep secret files from the Read tool and the common
  shell readers, even in `bypassPermissions` mode, but an interpreter
  one-liner still reads them. Only the sandbox stops that, and it does not run
  on native Windows. `AGENTS.md` §11 says so.
- **H7.** Nothing ties each commit to a changelog entry: entries are not
  keyed to commits, so a mechanical check would be noise. CI runs the
  self-test on every push, and the maintenance steps in `_starter/README.md`
  put the entry first.
